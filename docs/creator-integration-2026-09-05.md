# Settings 모델 다운로드 · 채팅 생성 · H3 인코딩 캐시

## 사용 위치

- **Settings → 모델 다운로드**: Anima base / 2.9B / 3.8B, Krea2 생성·편집·업스케일, MiniMax H3 기본·Turbo·참조 영상·음성에 필요한 파일을 기능별로 선택한다.
- **Chat → 요청**: 자동 / 대화만 / 이미지 생성 / 영상 생성. 직접 선택한 이미지·영상 모드는 Ollama 모델 없이 동작한다. 자동은 최신 사용자 메시지의 명확한 생성 요청만 실행하며 프롬프트 작성·설명 요청은 대화로 남긴다.
- **Settings → 모델 다운로드 → H3 인코딩 캐시**: 사용 여부, 최대 용량(기본 8GB), 최대 항목 수(기본 32개), 서버 상태, 비우기.

## 다운로드와 모델 공유

설정된 주 모델 라이브러리, 다른 엔진의 공유 경로, 앱 모델 폴더 순서로 확인한다. 같은 기능팩이 공유하는 파일은 한 번만 준비한다. 다운로드 전에 표시된 파일별 실제 저장 위치와 필요한 용량을 확인할 수 있다.

기존 파일의 크기만 맞으면 `모델 발견`, SHA-256까지 확인하면 `SHA 검증됨`으로 구분한다. 기존 완성 파일은 자동으로 덮어쓰지 않는다. 다운로드는 앱 전용 `.part`에 저장하며 크기와 해시를 확인한 뒤 게시한다. 취소한 다운로드는 이어받을 수 있고, 서버가 Range를 무시하면 임시 파일에서 처음부터 다시 받는다. 잘못된 완성 `.part`는 `.invalid-UUID`로 보존하여 다음 재시도를 막지 않는다.

다운로드 기록·선택값은 `config/model_downloads/`에 저장한다. 카탈로그는 `core/model_download_catalog.json`에 버전 고정 URL, 크기, SHA-256을 함께 보관한다. GitHub 보조 파일 일부는 API가 SHA-256을 제공하지 않아 기존 감사에서 확인한 고정 해시를 사용한다. 이 한계는 카탈로그의 `integrityNotes`에도 기록한다.

H3 Turbo grid는 `ComfyUI-MiniMax-H3-Turbo`가 실제로 설치된 노드 폴더에만 저장한다. 해당 노드가 없으면 먼저 노드 설치를 안내한다. 노드 소스는 수정하지 않는다. 모델 다운로드는 엔진·확장 설치나 GPU 실행을 자동으로 시작하지 않는다. 로컬 설치 기능은 데스크톱 전용이며 웹 연결에서 설치 명령 및 로컬 경로 조회를 차단한다.

## 채팅 생성

`현재 선택 모델`은 T2I의 모델, LoRA, TE/VAE, 샘플링, Hires 및 후처리 설정을 캡처한다. 캡처 과정은 T2I 프롬프트나 해상도 입력을 바꾸지 않는다. 무거운 프롬프트 파일 처리는 생성 작업에서 수행한다. 참조 이미지 한 장을 첨부하면 현재 모델의 I2I 또는 Krea2 편집, H3 이미지 기반 영상으로 연결된다.

Krea2/H3는 현재 연결된 ComfyUI를 사용하며 필요한 모델·노드가 없으면 오류로 안내한다. 채팅의 H3는 기본 품질(20 steps)로 실행하므로 별도 Turbo 파일이 필수는 아니다. 현재 모델 생성도 기존 `ollamaUnloadOnGen` 설정을 따르며 언로드 통신은 작업 스레드에서 처리한다. 대화 결과에는 진행 상태와 생성 미디어를 표시한다. 재시도·참조 재사용·경로 복사·Markdown 내보내기를 지원한다. 각 생성 요청이 자신의 취소 상태와 백엔드만 소유하므로 다른 작업의 늦은 응답이 현재 대화를 완료하거나 중지하지 않는다.

## H3 캐시 동작과 범위

1. ComfyUI 서버에서 모델·입력 내용과 인코딩 코드의 식별값을 확인한다.
2. 캐시가 있으면 무거운 인코더 실행을 생략한다. 없으면 인코딩 결과의 CPU 텐서만 무결성 정보와 함께 저장한다.
3. 준비 노드 안에서 ComfyUI 모델 언로드·캐시 해제 호출이 끝난 뒤 완료 증빙을 반환한다. 비동기 `/free` 응답만으로 해제 완료를 추정하지 않는다.
4. 인코더가 없는 별도 워크플로에서 캐시를 읽어 영상 모델을 실행한다.

저장은 해당 ComfyUI의 `output/aistudio_cache/h3_conditioning/` 아래로 제한한다. 로컬 앱과 원격 서버의 파일 경로를 섞지 않는다. PyTorch `weights_only=True`로 읽고 손상된 항목은 재사용하지 않는다. 캐시 비우기는 전용 형식의 캐시 파일만 대상으로 하며 원본·모델·관계없는 파일은 보존한다. 서버가 작업 중이면 비우기를 거절한다.

캐시 노드가 없는 서버는 안내 후 기존 단일 워크플로로 생성한다. 노드팩 1.1.3 이상을 적용하고 ComfyUI를 재시작해야 캐시를 사용할 수 있다. 외부 클라이언트까지 독점 잠그는 프로토콜은 없으므로 다른 클라이언트가 캐시를 비우거나 제한으로 항목을 제거하면 단계 사이에 캐시 누락 오류가 발생할 수 있다. 잘못된 인코딩으로 조용히 생성하지 않고 다시 실행하도록 안내한다. `--gpu-only`처럼 중간 텐서도 GPU에 남기는 실행 옵션에서는 VRAM을 완전히 비운다고 보장하지 않는다.

모델 파일을 같은 이름으로 교체했을 때는 ComfyUI를 반드시 재시작해야 한다. 기본 로더가 이전 모델 객체를 메모리에 보관할 수 있기 때문이다. 캐시 노드가 이미 확인한 모델 내용이 바뀌면 재시작 오류로 중단한다. 다만 캐시 기능을 처음 사용하기 전에 기본 로더가 읽었던 모델의 이력까지 증명하지는 못한다.

## 검증 범위

작은 가짜 HTTP 응답을 통한 실제 다운로드 파일 쓰기·검증·취소·이어받기, CPU 텐서 캐시 저장/재사용/손상/용량 제한, 두 단계 실행 순서, 요청 ID와 취소 경합, 채팅 저장·복원, 브리지 계약을 자동 테스트한다.

`frontend/dev/creator-integration.html`은 `npm run dev`에서 여는 오프라인 화면 검증용 페이지다. 모든 요청은 메모리에서만 처리하며 다운로드·모델·실제 서버를 사용하지 않는다. Settings와 Chat의 실제 컴포넌트를 사용하지만 제품 빌드에는 포함하지 않는다. 이 페이지에서 설정 재진입, 다운로드 진행/취소, 채팅 이미지·영상 진행/실패/중지, 다크·라이트 및 390px 폭을 확인했다.

이번 검증에서는 대용량 모델 다운로드, 실제 GPU 이미지·영상 생성, 실제 H3 캐시 전후 성능 비교를 수행하지 않았다. 자동 테스트와 오프라인 UI 검증을 실제 모델의 생성 품질·VRAM 절감 효과 검증으로 해석하면 안 된다.

### 최종 회귀 검사 보완

- Search/Event 테스트 객체도 실제 `ModelDownloadActionsMixin`을 사용하도록 맞췄다. 기존 검색 결과·대기열·자동화 검증은 유지하며, 관련 없는 액션에서는 다운로드 작업이 시작되지 않는다.
- 새 `upscale_models` 분류를 정확한 경로 기대값에 반영했다. 공용 폴더의 기존 파일 보존, 공유 경로 중복 제거, Forge/Comfy 경로 구분 및 메인 UI 전환 후 설정 파일 순서를 함께 검증한다.
- `modelDownloadEvent`는 데스크톱 전용 예외로 명시했다. 실제 브리지 신호인지와 웹 허용 목록에 포함되지 않는지를 별도로 검증하며, 웹의 설치 명령·로컬 경로 접근 차단을 유지한다.
- 전체 Python 검사 두 차례 모두 총 1,206개 중 1,203개 통과·3개 건너뜀·실패 0개. 건너뛴 항목은 실제 Cosmos 통합 환경 미지정, PyAV가 설치된 환경의 미설치 분기, Windows 디렉터리 심볼릭 링크 권한 제한이다.
- 수정·추가 Python 32개 파일 문법 검사, 프론트 111개 테스트, 타입 검사 및 `frontend_dist` 제품 빌드 통과. 개발용 확인 페이지는 제품 빌드에 포함되지 않는다.

이번 회귀 수정에서는 외부 ComfyUI 설치 폴더의 노드팩 교체와 Git 커밋·푸시는 수행하지 않았다.
